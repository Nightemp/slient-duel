# slient-duel
# SILENT DUEL 🤠🔫

Дуэль на пистолетах с глушителем, один на один, от первого лица.
Telegram Mini App. Сервер на Node.js + Socket.io, хостинг — Render.

## Структура проекта

```
silent-duel/
├── package.json
├── render.yaml              ← конфиг автодеплоя на Render
├── .env.example             ← пример переменных окружения
├── server/
│   ├── index.js             ← точка входа: express + socket.io + запуск бота
│   ├── bot.js                ← Telegram-бот (кнопка "Начать дуэль")
│   ├── db.js                  ← база игроков (деньги, скины, статистика), файл server/db.json создаётся сам
│   ├── game/
│   │   ├── Room.js             ← вся логика дуэли: урон по частям тела, кто умер, кто хромает
│   │   └── matchmaking.js       ← очередь "на двоих" и хранение активных комнат
│   └── routes/
│       └── api.js               ← REST: /api/profile, /api/shop, /api/buy, /api/equip, /api/online
└── public/                    ← это и есть Web App, который открывается в Telegram
    ├── index.html
    ├── css/style.css
    └── js/
        ├── main.js             ← экраны меню/очереди/магазина/игры, вся связка с сервером
        └── game/
            ├── Scene.js         ← 3D-сцена, камера от первого лица, стрельба (Three.js)
            ├── Ragdoll.js        ← тело человека из частей + реакция на "перелом" руки/ноги
            ├── Blood.js           ← кровь при попадании
            └── UI.js               ← полоски HP по частям тела, счётчик онлайна, деньги
```

## Как это работает (коротко)

1. Игрок открывает бота в Telegram → жмёт "🔫 Начать дуэль" → открывается Web App (public/index.html).
2. Жмёт "Найти дуэль" → сервер ставит его в очередь (matchmaking.js). Как только наберётся 2 игрока — создаётся `Room`.
3. Игроки стоят друг напротив друга (камера от первого лица, соперник в 8 метрах).
4. Клик по экрану = выстрел. Клиент считает, в какую часть тела соперника попал луч (raycast Three.js), и просто ГОВОРИТ об этом серверу — а решает, сколько это стоит здоровья, именно **сервер** (`Room.applyHit`), чтобы никто не мог накрутить себе урон через консоль браузера.
5. У каждой части тела своё HP (голова/торс/руки/ноги) — с одного выстрела никто не погибает, нужно "расстреливать", как и просили (дикий запад, а не мгновенная смерть).
6. Если отстрелена правая рука — персонаж на сервере переключается на левую (`shootingHand`), и в 3D это сразу видно (пистолет переезжает в другую руку, рука безвольно повисает).
7. Если отстрелена нога — персонаж хромает (`canStand: false`), если обе ноги — падает и проигрывает.
8. Смерть = снесена голова, ИЛИ обнулён торс, ИЛИ отстрелены все 4 конечности.
9. Победитель получает +100$ (`db.registerWin`), деньги тратятся в магазине на скины костюма и модификации (быстрая перезарядка, твёрдая рука, плотное пальто).
10. Онлайн считается сокетами (`app.locals.onlineCount`) и показывается прямо в шапке экрана, над названием игры.

## Что нужно донастроить руками (это уже творческая часть, не код)

- **3D-модели**: сейчас тело — это простые капсулы/сферы (чтобы физика попаданий и переломов уже работала). Чтобы было "объёмно и реалистично", капсулы в `Ragdoll.js` нужно заменить на настоящую GLTF-модель человека в костюме (например, купленную/бесплатную на Sketchfab), сохранив имена частей (`head`, `torso`, `leftArm`, `rightArm`, `leftLeg`, `rightLeg`) — вся логика попаданий продолжит работать без изменений.
- **Анимации**: сейчас "перелом" конечности — это мгновенный поворот меша. Для настоящего рэгдолла на костях лучше подключить `cannon-es` и физические кости (это отдельный, более объёмный этап).
- **Звук выстрела с глушителем** и озвучка можно добавить через обычный `<audio>` в `Scene.js`.

## Установка и запуск локально

```bash
git clone <твой-репозиторий>
cd silent-duel
npm install
cp .env.example .env
# впиши в .env свой BOT_TOKEN (от @BotFather) и APP_URL (можно временно оставить пустым для локального теста)
npm start
```//

Сервер поднимется на `http://localhost:3000` — там уже открывается сама игра (без Telegram можно тестировать прямо в браузере, `tgUser` в этом случае будет `undefined`, и подставится гостевой ID).

## Деплой на GitHub + Render (пошагово)

### 1. Заливаем на GitHub
```bash
cd silent-duel
git init
git add .
git commit -m "Silent Duel: первая версия"
git branch -M main
git remote add origin https://github.com/ТВОЙ_НИК/silent-duel.git
git push -u origin main
```

### 2. Разворачиваем на Render
1. Зайди на render.com → New → Web Service.
2. Подключи свой GitHub-репозиторий `silent-duel`.
3. Render сам увидит `render.yaml` и предложит настройки — подтверди.
4. В разделе Environment добавь переменные:
   - `BOT_TOKEN` — токен от @BotFather
   - `APP_URL` — сюда впиши URL, который Render выдаст твоему сервису (например `https://silent-duel.onrender.com`) — **после первого деплоя** зайди и допиши эту переменную, потом Redeploy.
5. Дождись деплоя (кнопка "Live").

### 3. Настраиваем бота в @BotFather
1. `/newbot` (если ещё не создан) → получаешь `BOT_TOKEN`.
2. `/setmenubutton` → выбери своего бота → укажи URL = твой `APP_URL` — это добавит кнопку меню, открывающую игру.
3. Всё, можно писать боту `/start`.

### Важно про бесплатный тариф Render
Бесплатные веб-сервисы на Render "засыпают" без активности и просыпаются ~30-60 сек на первый запрос. Для реального проекта с живым онлайном стоит перейти на платный план, иначе игроки будут ждать при заходе после паузы.
